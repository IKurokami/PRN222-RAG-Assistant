====================================================================================================
3. FLOW 1 - DOCUMENT MANAGEMENT & INDEXING
====================================================================================================

HTTP request đích:

Document/Chapter Razor Page handler
  -> validate input/resource
  -> authorize Subject cụ thể
  -> persist thay đổi
  -> enqueue Document.Id khi cần indexing/re-index
  -> publish realtime event sau khi write thành công
  -> redirect/render giữ Subject context

Background indexing:

IDocumentIndexingQueue
  -> InMemoryDocumentIndexingQueue
  -> DocumentIndexingWorker
  -> IDocumentIndexingService
  -> PDF/DOCX/PPTX parser
  -> TextChunker
  -> ITextEmbeddingService
  -> replace DocumentChunk rows
  -> cập nhật IndexStatus
  -> publish DocumentIndexStatusChanged

Parser:
- PDF: PdfPig.
- DOCX/PPTX: DocumentFormat.OpenXml.

PageModel không parse/chunk/embed/query pgvector/call provider trực tiếp.

====================================================================================================
4. SIGNALR CHO DOCUMENT MANAGEMENT
====================================================================================================

Hub route đề xuất:

/hubs/documents

Event đề xuất:

DocumentCreated
DocumentUpdated
DocumentDeleted
DocumentIndexStatusChanged

Group đề xuất:

subject:{SubjectId}

Quy tắc bảo mật:
- connection/subscription phải authenticate;
- server phải kiểm tra quyền quản lý Subject trước khi join group;
- không tin SubjectId từ client như bằng chứng authorization;
- không broadcast event của Subject này sang Subject khác;
- chỉ broadcast sau khi write/index-state persistence thành công.

SignalR KHÔNG phải CRUD API.

Write path vẫn là:

browser form/fetch
  -> Razor Page handler
  -> antiforgery + validation + authorization
  -> persistence thành công
  -> realtime notifier / IHubContext
  -> clients cùng Subject được phép

Client cần automatic reconnect và phải chịu được event duplicate/out-of-order bằng stable ID hoặc re-fetch state.
PostgreSQL luôn là source of truth; SignalR chỉ đồng bộ UI realtime.

====================================================================================================
5. FLOW 2 - RAG CHAT
====================================================================================================

Chat hiện đã là Razor Pages.

Luồng backend:

selected Subject
  -> ChatSession.SubjectId
  -> IChatPageService cho page/session data
  -> IRagQueryService
  -> ITextEmbeddingService
  -> PgVectorDocumentChunkRetriever
  -> filter SubjectId + vector dimensions
  -> GroundedPromptBuilder + history
  -> IChatCompletionService
  -> parse citation markers
  -> persist ChatMessages + MessageCitations
  -> Razor Page Chat

Invariant:
- session thuộc authenticated user;
- Subject request phải nhất quán với persisted session;
- không fallback product path sang global corpus;
- không tạo citation giả khi không có evidence;
- chỉ citation thực sự được reference mới persist/render.

9. MULTI-SUBJECT VÀ RBAC
====================================================================================================

Persisted subject context:
- Chapter.SubjectId
- Document.SubjectId
- ChatSession.SubjectId

Roles:
- Admin
- SubjectLeader
- Student

Policies:
- ManageUsers     -> Admin
- ManageSubjects  -> Admin
- ManageDocuments -> Admin hoặc SubjectLeader

Admin quản lý mọi Subject tồn tại.
SubjectLeader chỉ quản lý Subject được assign.
Student không quản lý academic content.

ISubjectAccessService (hoặc application boundary tương đương) phải được giữ cho authorization Subject cụ thể.
UI ẩn button/link không bao giờ thay thế server authorization.

SignalR Document group phải dùng cùng subject authorization boundary.

====================================================================================================
10. AI PROVIDER VÀ EMBEDDING
====================================================================================================

Provider-neutral contracts:
- ITextEmbeddingService
- IChatCompletionService

Provider hỗ trợ:
- Ollama
- Gemini
- OpenAI
- OpenRouter

Đổi embedding provider/model/dimension => phải re-index toàn corpus.
Đổi chỉ Chat provider/model => không cần re-index.

PR #37:
- Gemini batch embedding gửi output dimensionality đúng config;
- pgvector retrieval lọc vector_dims trước cosine distance.

Different-dimension rows có thể tạm cùng tồn tại trong quá trình migration, nhưng khác embedding model vẫn không
được xem là cùng semantic vector space dù dimension giống nhau.

11. DATA PROTECTION
====================================================================================================

ASP.NET Core Data Protection keys được persist trong PostgreSQL qua DataProtectionKeyDbContext.
Điều này giữ key ring qua normal web-container restart nếu database vẫn tồn tại.

====================================================================================================
12. RENDER DEPLOYMENT + SIGNALR
====================================================================================================

Render hiện dùng Docker web service + PostgreSQL.

AI split:
- Chat: Gemini / gemini-3.6-flash
- Embedding: OpenRouter / nvidia/llama-nemotron-embed-vl-1b-v2:free
- Dimension: 1024

SignalR tương thích với Render web service vì Render hỗ trợ WebSocket connections.
Client vẫn phải reconnect vì deploy/platform maintenance có thể thay instance và đóng connection.

Hiện demo single-instance có thể dùng in-process SignalR fan-out.
Nếu sau này horizontal scale nhiều instance thì phải đánh giá scale-out/shared realtime state riêng.

Source file dưới /app/storage/uploads trên Render free vẫn ephemeral.
